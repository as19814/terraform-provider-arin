# Sandbox implementation coverage

Objective: implement all resources and data sources supported in ARIN's OT&E
sandbox. This file tracks remaining work; a passing test for one API family does
not establish coverage of another. Production mutations are outside testing scope.

The inventory starts with the official snapshots in `arin-api/README.md`. Each
family requires schemas, validated client behavior, Terraform lifecycle/import
where applicable, generated examples/docs, mock tests, and sandbox evidence.
Unsupported operations need documented, reproducible OT&E evidence rather than
being assumed out of scope. Reconcile this inventory against live documentation
again before declaring full coverage.

## Confirmed sandbox behavior

- AS-set POC links are generated by ARIN. Attempts to configure changed links
  return E_ENTITY_VALIDATION. They are computed attributes.
- Empty remarks elements cause HTTP 500. Omitting the element clears remarks.
- IRR route reads include autoLinkedRoaHandle for linked objects. The current
  route resource rejects those objects until coordinated RPKI support exists.
- mostSpecificNet requires an existing exact start/end range. Parent NET lookup
  is used to verify the registration covering a disposable host route.
- Both IPv4 /32 and IPv6 /128 disposable route lifecycles passed in OT&E.
- Route-set XML accepts the `^+` range operator in OT&E despite the web UI guide
  saying range operators are unsupported. Collection clearing and MNT membership
  round-trip successfully.
- IRR aut-num supports writable AS name, all six routing policy fields and
  membership in AS sets. Creation, changes, clearing, import and deletion passed
  without changing the underlying ASN registration.
- Customer records support creation, address/name/privacy updates, comment clearing,
  import and deletion. Updates preserve server-generated identity and registration
  date. Creation does not itself reassign a network.
- OT&E keys may differ from production because snapshots refresh monthly.

## Verification commands

- `make check`: vet, race tests, fake-server acceptance tests and binary build.
- `make generate`: reproducible provider documentation and examples.
- `ARIN_TEST_ORG_HANDLE=... make testlive`: explicitly read-only live tests.
- `ARIN_TEST_ORG_HANDLE=... make testote`: opt-in OT&E mutations on disposable objects.

Credentials, live account responses, state and saved plans must not be committed.
