# DNS delegation implementation evidence

The client supports full delegation updates, individual nameserver addition,
update and deletion, bulk nameserver deletion, and DNSSEC DS records. IPv4 and
IPv6 sandbox lifecycles pass. Terraform resource integration remains pending.

## Object lifecycle

ARIN's [reverse DNS guide](https://www.arin.net/resources/manage/reverse/) ties
delegation boundaries to the CIDR blocks in direct allocations. Creating a
disposable IPv6 /64 reallocation did not create a corresponding /64 delegation:
its GET returned 404. That test NET was deleted. Discover existing delegations
through the authenticated NET delegation-list endpoint rather than constructing
a zone name from an arbitrary reassignment prefix.

Delegation objects appear/disappear with their registrations. The API provides
no independent create/delete operation for a delegation object. A Terraform
resource must manage records on an existing zone and explicitly define whether
destroy clears those records or only relinquishes management.

## Payload behavior verified in OT&E

The saved [method](arin-api/reg-rws/methods.md) and
[payload](arin-api/reg-rws/payloads.md) guides are reference inputs; the following
differences were verified against OT&E:

- Full PUT must include the existing `name`. Omitting it returns E_BAD_REQUEST
  because the name cannot be modified, despite the payload guide advising that
  it be left blank.
- Nameserver TTL is an attribute in `http://www.arin.net/regrws/ttl/v1`.
- DS TTL is an element in that same TTL namespace. An unqualified/core TTL
  element returns E_SCHEMA_VALIDATION.
- Full replacement uses explicit empty `nameservers` and `delegationKeys`
  containers to clear both collections. This was verified, not inferred from
  the individual DELETE endpoints.
- Nameserver TTL omission resets the record to inherited TTL, including when
  using the single-nameserver POST method.
- Omitting TTL on an existing DS record preserves its previous explicit TTL.
  Omitting TTL on a new DS record yields an inherited/null TTL. Terraform must
  account for this distinction rather than assume omission always clears TTL.
- Numeric DNSSEC algorithm/digest-type IDs are writable; their display names
  are generated by ARIN. Algorithm 13 and digest type 2 were tested.
- DNS names returned by the API are normalized to lowercase, and nameservers
  omit the trailing dot in the typed client. Delegation names retain it.

## Validation and recovery

`TestOTEDelegationClientLifecycle` selects an existing delegation under an owned
direct allocation in each address family. It verifies full nameserver replacement,
explicit/inherited TTLs, DS addition/replacement/clearing, single nameserver
addition/update/deletion, bulk deletion and a fully empty PUT.

Before any mutation, it creates a mode-0600 JSON recovery file under the user's
cache directory, in `terraform-provider-arin/ote-delegation-<zone-hash>.json`.
The backup contains the original delegation model and no API credentials.
The file is created exclusively and synced to disk; an existing file blocks a
new test run instead of overwriting recovery data.

Cleanup restores the original delegation, reads it again, compares all typed
fields, and removes the recovery file only after verification. A restoration
failure retains the file and reports its path. Investigate and restore that
snapshot against OT&E before rerunning; do not remove it merely to bypass the
test's recovery guard.

Normal unit tests and CI do not enable sandbox writes. Explicit opt-in requires
`ARIN_OTE_WRITE_TESTS=1`, `TF_ACC=1`, `ARIN_OTE_API_KEY`, and
`ARIN_TEST_ORG_HANDLE`. Both service origins are fixed to OT&E in the live test.

The client validates zone names, hostnames, TTL bounds, DS numeric fields, digest
encoding and duplicate records. It rejects unknown response fields before full
writes and does not retry mutations automatically. Mock tests cover the live
namespace/name requirements, explicit clearing, request paths, read failures and
failed-write behavior.
